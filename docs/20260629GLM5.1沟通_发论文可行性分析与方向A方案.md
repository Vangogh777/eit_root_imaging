## 二、要加的原创模块

### 模块 1: Physics-Aware Message Passing (PAMP) — 核心创新 ⭐⭐⭐

#### 2.1.1 动机

当前 GNN 的消息传递完全数据驱动，与 EIT 物理无关：

```
标准消息:  m_{i→j} = MLP([h_i, h_j]) · w_{ij}
```

但 EIT 的 FEM 网格不是任意图——它来自物理离散化，每条边有**物理含义**：两个相邻三角单元共享节点，电场在它们之间连续。Jacobian 矩阵的列向量编码了每个单元对测量的灵敏度，而两个相邻单元的**互灵敏度**（J 交叉项）衡量了它们之间的电磁耦合强度。

**没有任何现有 EIT+GNN 论文利用了这个物理信息。**

GraphEIT 的 GNN 是纯数据驱动的；Graph U-Net (Herzberg) 用了 Jacobian 做后处理但没嵌入消息传递；CNN+PINN (Yang) 用了 PDE 但在像素域。

#### 2.1.2 设计

将 Jacobian 互灵敏度注入 GNN 消息传递，使消息的**方向和强度**受物理约束。

**物理边特征**: 只用 2 维纯 Jacobian 特征（见自检3：contiguity 有训练/推理不一致问题，已去掉）

- `J_mutual`: Jacobian 列余弦相似度 — 两个单元对测量的联合影响
- `J_ratio`: 灵敏度范数比 (log) — 不对称，反映测量对不同位置的敏感度差异

```python
class PhysicsAwareMessagePassing(nn.Module):
    """
    物理感知消息传递层

    与标准 GNN 的区别：
    1. 边权重受 Jacobian 灵敏度门控调制
    2. 消息内容包含物理特征（J_mutual + J_ratio）
    3. 聚合按灵敏度加权，而非均匀/学习加权
    """
    def __init__(self, in_dim, out_dim, dropout=0.1):
        super().__init__()
        # 消息网络：输入 [h_i, h_j, phys_ij]
        self.message_mlp = nn.Sequential(
            nn.Linear(in_dim * 2 + 2, out_dim),  # +2: 2个Jacobian物理特征
            nn.LayerNorm(out_dim),
            nn.GELU(),
            nn.Dropout(dropout),
            nn.Linear(out_dim, out_dim),
            nn.LayerNorm(out_dim),
        )
        # 灵敏度调制门控
        self.sensitivity_gate = nn.Sequential(
            nn.Linear(2, 16),
            nn.GELU(),
            nn.Linear(16, 1),
            nn.Sigmoid(),
        )
        # 更新网络
        self.update_mlp = nn.Sequential(
            nn.Linear(in_dim + out_dim, out_dim),
            nn.LayerNorm(out_dim),
            nn.GELU(),
        )

    def forward(self, h, edge_idx, edge_weight, phys_edge_feat):
        """
        h: (B, N, in_dim)
        edge_idx: (2, E)
        edge_weight: (E,)
        phys_edge_feat: (E, 2) Jacobian物理边特征:
            [0] J_mutual: 列余弦相似度
            [1] J_ratio: 灵敏度范数比
        """
        B, N, D = h.shape
        src, dst = edge_idx

        gate = self.sensitivity_gate(phys_edge_feat)  # (E, 1)
        h_src = h[:, src]
        h_dst = h[:, dst]
        phys = phys_edge_feat.unsqueeze(0).expand(B, -1, -1)
        msg_input = torch.cat([h_src, h_dst, phys], dim=-1)
        msg = self.message_mlp(msg_input)
        msg = msg * gate.unsqueeze(0)

        h_agg = torch.zeros(B, N, msg.shape[-1], device=h.device)
        weighted_msg = msg * edge_weight.view(1, -1, 1)
        h_agg.scatter_add_(1, dst.view(1, -1, 1).expand(B, -1, msg.shape[-1]), weighted_msg)

        h_new = self.update_mlp(torch.cat([h, h_agg], dim=-1))
        return h_new
```

#### 2.1.3 物理边特征计算

```python
def _compute_physics_edge_features(self, jacobian, edge_list):
    """
    jacobian: (n_meas, n_elems) 单频灵敏度矩阵
    edge_list: (2, n_edges) 有向边索引
    返回: (n_edges, 2) 物理边特征
    """
    J = jacobian
    J_norm = np.linalg.norm(J, axis=0)  # (n_elems,)
    n_edges = edge_list.shape[1]
    phys_feat = np.zeros((n_edges, 2), dtype=np.float32)

    for e in range(n_edges):
        i, j = edge_list[0, e], edge_list[1, e]
        if i == j:
            phys_feat[e] = [1.0, 0.0]  # self-loop: 完全相关, 等灵敏度
            continue
        J_i, J_j = J[:, i], J[:, j]
        norm_ij = np.linalg.norm(J_i) * np.linalg.norm(J_j) + 1e-12
        # 特征0: 互灵敏度 (cosine similarity of J columns)
        phys_feat[e, 0] = np.dot(J_i, J_j) / norm_ij
        # 特征1: 灵敏度比 (log ratio, 不对称)
        phys_feat[e, 1] = np.log(J_norm[i] / (J_norm[j] + 1e-12) + 1e-6)

    # 归一化
    phys_feat[:, 0] = (phys_feat[:, 0] + 1) / 2       # cosine [-1,1] → [0,1]
    phys_feat[:, 1] = np.clip(phys_feat[:, 1], -3, 3) / 3  # log ratio → [-1,1]

    return phys_feat
```

#### 2.1.4 为什么这是原创的

| 对比 | GraphEIT (2024) | Graph U-Net (2023) | CNN+PINN (2025) | **我们的 PAMP** |
|------|-----------------|-------------------|-----------------|----------------|
| GNN 消息传递 | 纯数据驱动 | 纯数据驱动 | 无 GNN | **Jacobian 互灵敏度调制** |
| 物理信息 | Fourier 位置编码 | 无 | PDE 残差 | **Jacobian 列间耦合** |
| 边特征 | 距离/共享节点 | 无 | 无 | **灵敏度比+互灵敏度+连续性** |
| 物理与图的关系 | 图结构=物理网格，但消息无物理 | 图结构=物理网格 | 无图 | **图结构=物理网格 + 消息=物理耦合** |

**核心理论故事**：

> EIT 的 FEM 网格不是任意图——它的边来自物理离散化，每条边对应电磁场的连续性约束。
> 两个相邻单元之间的 Jacobian 互灵敏度编码了它们对边界测量的**联合影响**——高互灵敏度意味着它们"在测量看来是一体的"，消息应该强耦合；低互灵敏度意味着它们对测量的贡献独立，消息应该弱耦合。
> Physics-Aware Message Passing 将这种物理耦合嵌入 GNN 的消息传递机制，使得图上的信息流动与 EIT 正问题的物理结构一致。

```python
def setup_mesh(self, centers, elements, jacobian=None, sigma_ref=0.01):

    if jacobian is not None:

def _compute_physics_edge_features(self, jacobian, edge_list):
    J = jacobian  # (n_meas, n_elems)
    J_norm = np.linalg.norm(J, axis=0)  # (n_elems,)
    n_edges = edge_list.shape[1]
    phys_feat = np.zeros((n_edges, 3), dtype=np.float32)
    
    for e in range(n_edges):
        i, j = edge_list[0, e], edge_list[1, e]
        if i == j:  # self-loop
            phys_feat[e] = [1.0, 0.0, 0.0]
            continue
        J_i, J_j = J[:, i], J[:, j]
        # 互灵敏度 (cosine similarity)
        norm_ij = np.linalg.norm(J_i) * np.linalg.norm(J_j) + 1e-12
        phys_feat[e, 0] = np.dot(J_i, J_j) / norm_ij
        # 灵敏度比 (log ratio)
        phys_feat[e, 1] = np.log(J_norm[i] / (J_norm[j] + 1e-12) + 1e-6)
        # 场连续性 (初始0, 推理时动态)
        phys_feat[e, 2] = 0.0
    
    # 归一化到合理范围
    phys_feat[:, 0] = (phys_feat[:, 0] + 1) / 2  # cosine [-1,1] → [0,1]
    phys_feat[:, 1] = np.clip(phys_feat[:, 1], -3, 3) / 3  # log ratio → [-1,1]
    
    return phys_feat
```

### 4.1 架构消融（修正版——控制变量设计）

| 实验 | GNN 类型 | 边特征类型 | J^T·r | 验证目标 |
|------|---------|-----------|-------|---------|
| **A1** | PAMP | Jacobian物理 (2维) | ✅ | **完整模型 (论文方法)** |
| **A2** | SimpleGNN | Jacobian物理 (2维) | ✅ | 控制特征相同，只换消息传递机制 → **隔离 PAMP 机制的贡献** |
| **A3** | PAMP | 几何特征 (原有4维) | ✅ | PAMP 机制+几何特征 → **隔离 Jacobian 物理特征 vs 几何特征的贡献** |

关键对比：
- **A1 vs A2**: 同特征不同机制 → PAMP 门控+物理消息传递的纯机制贡献

### 8.3 残留风险（必须正视）

#### 风险 1: PAMP 改进可能微弱（天花板效应）⚠️⚠️

当前 ConvSpatialEIT RE=0.07 已经很低。PAMP 在此基础上能降多少？

- 如果 RE=0.07 → 0.05：改进 28%，但绝对值小，可能统计不显著
- 如果 RE=0.07 → 0.07：PAMP 无贡献，**整个创新点不成立**

**缓解措施**：
- 在更难的场景下测试（混合数据集、噪声、跨形状泛化），PAMP 可能在此类场景下优势更明显
- 不只看 RE，还看 CC、边缘保持度、噪声鲁棒性等指标
- **必须先做 PAMP vs baseline 的快速对比实验（10-20 epoch），确认有改进趋势再投入完整训练**

#### 风险 2: 审稿人认为 PAMP 只是特征工程 ⚠️

"把 Jacobian 特征加到边上是特征工程，不是架构创新"

**缓解措施**：
- B5 消融（Jacobian 加权聚合 vs PAMP 门控）证明门控机制有额外贡献
- 理论叙事强调"消息传递方向与 EIT 物理结构一致"，而非简单特征注入
- 如果 B2（无门控）和 B1（有门控）差异显著，说明门控本身有价值

#### 风险 3: PAMP vs J^T·r 信息重叠 ⚠️

J^T·r 已经用了 Jacobian，PAMP 又用——信息冗余？

**缓解措施**：
- A3（PAMP 无 J^T·r）消融直接回答这个问题
- 叙事上区分：J^T·r 是全局残差校正（输出层），PAMP 是局部消息调制（中间层）
- 不同层级注入不同粒度的物理信息

#### 风险 4: 只有合成数据，无真实实验 ⚠️

**缓解措施**：
- 目标投 Neurocomputing / Neural Networks（接受纯仿真）
- 论文 Discussion 中明确说明局限性和未来真实数据验证计划
- CDEIT (IEEE TIM) 有真实数据但也是以仿真为主

### 8.4 关键决策点

在正式投入完整训练之前，**必须先做以下验证**：

```
if PAMP 快速训练 (20 epoch) 的 RE 不低于 SimpleGNN baseline:
    → 继续 PAMP 完整训练
else:
    → PAMP 无效，需要换方向
    → 可选备选: (a) 换更复杂的门控机制 (b) 用 attention-based Jacobian 注入
               (c) 放弃 PAMP，改为纯应用驱动论文 (农业EIT)
```
