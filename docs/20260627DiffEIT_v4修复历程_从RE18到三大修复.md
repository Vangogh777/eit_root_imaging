# DiffEIT v4 修复历程：从 RE=18 到三大修复

> 2026-06-27 | 完整记录一天内的诊断、错误和修复方向

---

## 1. 起点：v4 训练 RE=2~4

**现象**：DiffEIT v4 在原始数据上训练，val_loss≈0.14（看起来很低），但 val_RE=2~4，比全预测背景（RE≈0.5）还差 3-6 倍。

**诊断**：
- 数据每样本仅 2 个 σ 值（硬边界 phantom）：背景=0.01，内含物=某个固定值
- 标准化后分布极端非高斯：95% 元素=-0.22σ，5% 元素=+2~+6σ
- 加权 MSE（异常 15x 权重）推动模型输出全异常级 σ 值

**修复**：
- 数据加图 Laplacian 平滑（1 iteration, strength=0.10）：2 个值 → 19~35 个连续值
- 加权 MSE → 简单 MSE
- 物理一致性 λ: 0.05 → 0.3
- 输出头 Linear → Tanh

---

## 2. 错误 1：过早引入多背景数据

**做了什么**：按设计文档要求加入 6 档背景 σ（0.005~0.3），让模型学习域泛化。

**结果**：val_RE 从 2~4 暴增到 **18**。

**根因**：多背景 + 全局线性标准化 = 分布灾难。
- BG=0.005 样本的背景映射到 -0.4σ
- BG=0.3 样本的背景映射到 +1.8σ（被认为"异常"！）
- BG=0.3 样本的内含物映射到 +16σ（远超 Tanh[-1,1]）
- 模型无法区分"高背景中的正常区域"和"低背景中的异常区域"

**教训**：多背景数据需要 RankGauss 或 per-sample 标准化做前提。不能直接加。

**修复**：回退到统一 BG=0.01，先验证基础能力。

---

## 3. 修复：RankGauss 标准化

**问题**：线性两步标准化 `(σ-min)/range → (norm-mean)/std` 无法将偏态分布转为正态。

**实现**：
```python
# 构建 RankGauss 查找表（训练前一次性计算）
sorted_vals = np.sort(sample_from_training_data)  # 10000 分位点
quantiles = np.linspace(0, 1, 10000)
gauss_vals = sqrt(2) * erfinv(2 * quantiles - 1)  # 分位数 → N(0,1)

# Forward: σ_phys → searchsorted → σ_std (真正 N(0,1))
# Sample: σ_std → searchsorted(reverse) → σ_phys
```

**效果**：数据在扩散空间真正 N(0,1)，分布 skew≈0, kurt≈3。

---

## 4. 错误 2：RankGauss 表未保存到 checkpoint

**做了什么**：RankGauss lookup tables 用 `register_buffer(..., persistent=False)` 注册。

**结果**：checkpoint 不包含 RankGauss 表！加载模型做推理时 rg_* 为空张量，IndexError。

**根因**：`persistent=False` 意味着 buffer 不参与 `state_dict()`，不会被 `torch.save()` 保存。

**修复**：改为 `persistent=True`。

---

## 5. 错误 3：只监控 val_loss，忽略 val_RE

**问题**：训练日志只显示 val_loss（单步去噪 MSE），不显示 val_RE（完整 DDIM 生成质量）。

**val_loss 的欺骗性**：
- val_loss 在 epoch 10 已经降到 0.068，看起来很好
- 但 val_RE=2.39，模型完全不能用
- 单步去噪 MSE 低 ≠ 迭代生成质量好

**根因**：val_RE 存在 events.jsonl 中，首页只读 epochs.jsonl。两边数据不互通。

**修复**：val_RE 同时写入 log_epoch（`re=val_re`）和 log_event。

---

## 6. 核心发现：单步去噪学会 ≠ 迭代生成学会

### 诊断实验

对 epoch 10 的 best 模型运行推理，发现：

| 发现 | 数据 | 含义 |
|------|------|------|
| DDIM 步数越多越差 | RE_10=1.80 < RE_50=1.89 < RE_100=1.95 | 预测在往错误方向累积 |
| 输出范围恒定 | pred 永远 [0.0095, 0.0962] | 不管输入是什么，模型输出全范围 |
| 电压条件作用弱 | 有电压 RE=1.92, 无电压 RE=3.03, ratio=1.58x | 条件注入几乎没被用到 |

**结论**：模型学到了"输出应该覆盖全 σ 范围"但没有学到"异常在哪里"。FiLM 条件注入被模型忽略了。J^T·V 灵敏度特征只在输入层注入，信息流在深层丢失。

## 7. 三大修复（当前训练中）

### ① J^T·V 输出偏置（spatial prior）

```python
# models/diff_eit.py
self.sens_bias = nn.Sequential(
    nn.Linear(2, 16), nn.GELU(),  # J^T·V + J_energy → bias
    nn.Linear(16, 1),
)

# forward():
bias = self.sens_bias(extra_feat)       # (B,N,2)→(B,N,1)
sigma_0_pred = sigma_0_pred + 0.1 * bias  # 直接加到去噪器输出
```

**为什么有效**：J^T·V 是 GREIT 的核心操作——电压通过灵敏度反投影到空间域。正值=可能高于背景，负值=可能低于背景。直接加到输出告诉模型"这里可能有异常"。

### ② Classifier-Free Guidance

```python
# 训练: 15% 概率丢电压条件
if training and random() < 0.15:
    v_emb = zeros; extra_feat = None  # 无条件

# 推理: CFG 放大条件信号
pred = pred_uncond + 1.5 * (pred_cond - pred_uncond)
```

**为什么有效**：训练时见过无条件，推理时通过插值放大"条件告诉我什么"。无条件预测=通用先验，有条件预测=特定于这个样本的调整。CFG 让模型必须学会利用电压。

### ③ T=50（减少扩散步数）

```
T=200 → T=50
每步 SNR 更高 → 模型单步预测更可靠 → 误差累积更少
训练速度不变（随机采样 t），推理速度快 4x
```

## 10. 教训总结

1. **val_loss ≠ 模型质量**。扩散模型必须直接监控生成指标（val_RE）
2. **数据问题在代码问题之上**。二值分布、多背景标准化——这些是扩散模型不能正常工作的根本原因
3. **先简单后复杂**。先统一 BG 验证基础能力，再逐步加多背景
4. **persistent=True**。需要保存到 checkpoint 的 buffer 不能设 persistent=False
5. **条件注入需要"硬连接"**。仅靠 FiLM 不够，J^T·V 应该直接加到输出
6. **CFG 是必需品不是可选项**。条件扩散模型没有 CFG 很难有效利用条件
